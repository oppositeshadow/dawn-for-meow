# 《喵星破晓》开发流程

本项目是单机挂机游戏，**文档即规格**，代码只是实现。任何改动都按下面四条流程走。

## 一、改数值（产出 / 造价 / 成本 / 系数）

1. **先改 `数值平衡表.md`**（唯一真值），在对应小节写清新值 + 修订记录一行；
2. **同步种子**：`backend/static/*.json`（注意保持 UTF-8）；
3. **同步常量**：`backend/app/core/balance.py`（`FACILITY_SPECS` / `TECH_TIER_COSTS` / 各种 `*_MULTIPLIER`）；
4. **跑 `python -m pytest tests/test_models_and_init.py`** —— 有"种子 ⇄ balance 不漂移"的一致性测试；
5. **复算影响**：跑对应只读脚本（`scripts/pacing_analysis.py` 看科技节奏、`scripts/armor_curve_analysis.py` 看战斗曲线），把改前改后的数字贴给用户看；
6. **若影响既有平衡**（例：改减伤曲线会让高装甲单位集体变弱），**先把选项与量化影响摆出来让用户拍板**，不要自作主张。

## 二、加新机制

1. **登记作用域**（`代码结构稿` §7 三问）：母星专属 / 每星球独立 / 存档级，三选一；
2. **母星专属** ⇒ 必须加显式校验 + 明确错误码（参考 `COLD_START_HOME_ONLY` / `LAUNCH_SILO_HOME_ONLY`）；
   **每星球独立** ⇒ 建行要加到 `planet_service.STAR_COLONY_TABLES` 并真的建出该行（`test_scope_matrix` 会验）；
   **存档级** ⇒ 表只带 `slot_id`，`test_scope_matrix` 会静态断言主键（防止被"顺手"改成按星球分裂）；
3. **效果载荷**：数值型效果要么进 `balance.TECH_ACTIVE_EFFECT_KEYS` 白名单（真结算），要么留在 `pending_effects`（只展示）。
   **语义不唯一或会重复记账的键（例：`vs_shield` 与全局相克表重复）先记进 §6.4.1 红灯区，定稿后再接**；
4. **加成一律"相加不相乘"**（除非定稿明确说相乘）：`废铁系数 = 本星 1.25 + 设施 0.35`；
5. **前端只读不算**：系数从后端接口来（如 `planet_traits`），别在前端再写一套。

## 三、半截链路审计（每次上线新玩法后跑一遍）

1. **用玩家视角从头走**：新内容能不能真的走通？（历史坑：外星球初始资源 0 + 航线只能运猫 ⇒ 永远造不出第一座纸箱窝）
2. **检查机制越界**：只在母星合理的动作，在外星球是否也能用？（坑：手点废墟、发射井）
3. **检查反向**：本该每星球可用的系统，在外星球是否真的可用？（坑：`garden_state` 当时只是"应该可以"，补用例才算）
4. **检查存档级是否会分裂**：开分基地后深网行情、终局进度是否仍只有一份？
5. 发现不一致 ⇒ 修掉 + 加进 `tests/test_scope_matrix.py` 或对应模块用例，**别只改代码不加断言**。

### 三·三、跨存档状态泄漏（默认值深拷贝）

* **规则**：用模块级默认值初始化存档时，若默认值里含**嵌套可变对象**（列表 / 子字典），必须 `copy.deepcopy`，
  不能用 `dict(...)` 浅拷贝。
* 历史 bug：`DEFAULT_SECURITY_POLICY` / `DEFAULT_BOMBARDMENT_STATE` 里的 `damaged_facilities: []` 被所有新存档共享
  ⇒ 一次轰炸受损会"继承"给之后创建的每个档；表现是**测试偶发失败**（同库不同顺序结果不同，排查了好几轮）。
* 检查命令：`rg -n "dict\(DEFAULT_" backend/app`（应只剩 deepcopy 写法）。

### 三·四、"白名单登记 ≠ 接线"（自查清单）

> **顺带记住"新字段要三处同步"**：引擎里写了新字段 ≠ 接口能看到。必须同时改
> ① `offline_engine.build_report_summary`（或对应裁剪函数）② `schemas/*.py`（Pydantic 会**静默丢弃**未声明字段）
> ③ 前端 `types/game.ts` 与渲染层。这个坑已经踩过 5 次（`launch_silo` / `smelted_batches` / `gained_alloys` /
> `research` / `gained_unity`），每次症状都一样：代码写了、日志有数、接口里查无此字段。

把某个效果键写进 `WIRED_EFFECTS` / `TECH_ACTIVE_EFFECT_KEYS` **只是登记，不等于它真的参与结算**。
接线完成的唯一证据是：**引擎里有一处 `get_*_effects()` 的返回值被乘/加进公式**，并且**有用例证明数字变了**。

* 自查命令：`rg -n "active_effects|unlocked_effects" backend/app/core backend/app/services` —
  如果某个 `*_effects()` 只出现在 service 里、没有被 `colony_service` / `offline_engine` / `combat_service` 调用，就是假接线；
* 真接线的四处样板（2026-09-14 补齐）：生产效率 → `build_engine_state` 的 `production_multiplier`；
  承载力 → `cat_capacity_on(extra_multiplier=…)`；警戒度增速 → `suspicion_growth_multiplier`；
  载具装甲 → `combat_service._fleet_armor_bonus`；
* 每个新接线的效果**必须配一条"数字真的变了"的用例**（例：点亮政令后产出 ×1.2、承载力 10 → 11）。

## 三·二、多条件依赖走查（"静默失败"专项）

新机制只要同时依赖**资源 + 电力 + 科技门槛**，就要人工走一遍"条件不满足"的分支：

* 断供会变成"数字不动"而不是报错的，**必须有界面引导**（例：图灵终端净电力为负 ⇒ 科研归 0，
  科技面板要直接说"造两座猫力发电滚轮并派猫踩轮"）；
* 已知的早期依赖链（真机演练实测）：图灵终端要**芯片**（拾荒猫 0.01/s ⇒ 先挂机约 15 分钟）
  → 终端 **−6 kW** 会断电停科研 → 太阳能被 T1【瓦楞纸结构力学】挡着
  → 早期唯一出路是**猫力滚轮 ×2 + 踩轮猫 ×2**（开荒豁免名单内；**1 只踩轮猫只有 +5 kW，抵不过 −6 kW**）
  → 踩轮猫占猫口 ⇒ 派极客前要再扩窝；
* **粮食与人口必须同步扩**：猫薄荷见底时士气系数降到 **0.7**，农夫有效产出只剩 `0.2 × 0.7 = 0.14/s`，
  而每只猫吃 `0.05/s` ⇒ **1 个农夫在低士气下只养得起约 2.8 只猫**（不是直觉的 4 只）。人口先涨、粮食没跟上
  ⇒ 断粮 ⇒ `gained_research` 归零 ⇒ **科研静默停摆**；
* **工位来自设施**：1 座水培农田只有 2 个农夫工位 ⇒ 想上第 3 个农夫必须先建第二座农田；
* **长挂机会触发静默关灯**：警戒度被推满后三级安防预案启动，**全员停工**（科研/拾荒一并归零，报表里才有 note）。
  玩家要自己处理（造【隔音层】降噪、种【消音绒草】、或用诱饵/战车截杀）；演练脚本用测试专用 `calm()` 跳过，
  **真实玩家没有这个口子**；
* 走查工具：`python scripts/e2e_cold_start.py 3 --reset --stage mid`（只动测试槽位 2/3，拒绝碰主档）。

### 三·五、契约扫查（幽灵值 / 缺字面值 / 崩溃）

两个不同层次的问题，两种工具：

1. **照文档原文发一次请求** —— 专治"文档写了字面值但代码不认"（幽灵值）或"文档没给字面值、客户端写不出来"。
   实测抓到：`/darknet/stock/trade` 的 `action` 文档写三个值、代码只认两个（`CLOSE_LONG` 是幽灵值）。
2. **`python scripts/contract_sweep.py 3`** —— 给每个接口发一次"最小请求"（GET 带 slot、POST 只带 `{"slot": N}`），
   专治 **5xx**（输入没防住导致崩溃）。预期结果大多是 400（校验层正常工作），出现 5xx 就要查。
   2026-09-14 首扫：42 个接口 0 个 5xx（18×200 / 23×400 / 1×409），说明校验层完整。
3. 顺带核对：脚本的接口总数应与 `scripts/api_doc_consistency.py` 的真实接口数一致，
   不一致说明扫查漏了方法（当前只扫 GET/POST）。
4. **别只看崩溃数**：脚本还会列出"最小请求就返回 200 的 POST"——那可能是**静默接受残缺输入**。
   逐个复核"为什么它能 200"（2026-09-14 首轮：`scavenge` / `reroll-id` 本就不需要额外字段、
   `snapshot` 字段全可选、`radio/generate` 是默认参数 + 诚实兜底，均属正常）。

## 四、每轮收尾

0. **汇总数字必须从代码算**：接口数、设施数、节点数这类"总计"不要引用文档里手写的数字——
   跑 `python scripts/api_doc_consistency.py`（接口账本）、`scripts/pacing_analysis.py`（科技节奏）等只读脚本得出。
   历史教训：文档修订记录里写着"接口 69 个"，真实代码只有 **43 个**（多算了 26 个），一路抄了好几轮才发现。

1. `python -m pytest -p no:cacheprovider -q`（在 `backend/` 下；沙箱内 pytest 挂起时加 `-p no:cacheprovider`）；
2. 前端改动跑 `npm run build`（含 `vue-tsc` 类型检查）；
3. 真机抽查：重启 8010 端口的 uvicorn，用一个**测试槽位**（别动用户的主档）打一次真实接口；
4. 文档修订记录三处各写一行（数值 / 数据模型 / 工程）；
5. 提交：`git add -A; git commit -q -m "<模块>：<一句话>"`（沙箱内写 `.git` 需要 `require_escalated`）。

## 五、风格约定

* 中文提交信息、极简；提交信息不暴露实现内幕；
* 文档里**不许写未落地的功能当已实现**，要写就标"待落地"；
* 面向用户的提示语要**给出理由**（例："本地废铁 ×1.25，先铺产出"），不要只下命令。
